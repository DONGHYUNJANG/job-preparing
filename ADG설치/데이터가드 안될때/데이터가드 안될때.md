# 데이터가드 안될때

Oracle Data Guard에서 **Primary → Standby 동기화가 아무리 해도 안 될 때** DBA들이 실제로 확인하는 핵심 체크리스트를 **문제 발생 순서 기준으로** 정리해보겠습니다.

(실무에서는 보통 아래 순서대로 확인합니다.)

<aside>
💡

TNSPING 필수!!

</aside>

---

# 1️⃣ Primary에서 redo 전송 자체가 되는지

가장 먼저 **Redo Transport 상태** 확인

```sql
SELECT dest_id, status, error, destination
FROM v$archive_dest
WHERE target='STANDBY';
```

정상 예

```
STATUS : VALID
ERROR  : (NULL)
```

문제 예

```
STATUS : ERROR
ERROR  : ORA-xxxx
```

또는

```sql
SELECT dest_id, status, error
FROM v$archive_dest_status;
```

---

# 2️⃣ Standby redo log (SRL) 존재 여부

동기 모드에서는 **Standby Redo Log가 없으면 실시간 적용이 안 됩니다.**

Primary

```sql
SELECT group#, thread#, bytes
FROM v$standby_log;
```

없다면 생성

```sql
ALTER DATABASE ADD STANDBY LOGFILE SIZE 1G;
```

권장 개수

```
SRL >= Online Redo Log + 1
```

---

# 3️⃣ 네트워크 연결 (가장 많이 걸림)

Redo transport는 결국 **TNS 연결**입니다.

Primary에서 확인

```
tnsping standby
```

또는

```
sqlplus sys@standby as sysdba
```

로그도 확인

```
listener.log
alert.log
```

---

# 4️⃣ ARCHIVELOG / FORCE LOGGING

Primary에서 필수

```sql
ARCHIVELOG
FORCE LOGGING
```

확인

```sql
SELECT log_mode, force_logging
FROM v$database;
```

정상

```
LOG_MODE      ARCHIVELOG
FORCE_LOGGING YES
```

---

# 5️⃣ Standby Managed Recovery 실행 여부

Standby에서 recovery가 안 돌아가면 동기화 안 됩니다.

```sql
SELECT process, status
FROM v$managed_standby;
```

정상 예

```
MRP0 APPLYING_LOG
RFS  RECEIVING
```

없다면 실행

```sql
ALTER DATABASE RECOVER MANAGED STANDBY DATABASE
USING CURRENT LOGFILE DISCONNECT;
```

---

# 6️⃣ Archive gap 확인

로그가 중간에 빠지면 apply가 멈춥니다.

Standby에서

```sql
SELECT * FROM v$archive_gap;
```

결과 예

```
THREAD# LOW_SEQUENCE# HIGH_SEQUENCE#
1       1001          1005
```

이 경우 missing archive를 Primary에서 복사해야 합니다.

---

# 7️⃣ 실제 로그 적용 상태

Primary / Standby 비교

Primary

```sql
SELECT MAX(sequence#) FROM v$archived_log;
```

Standby

```sql
SELECT MAX(sequence#) FROM v$archived_log WHERE applied='YES';
```

차이가 크면

```
redo apply 멈춤
```

---

# 8️⃣ alert.log 확인 (가장 중요)

실무에서 가장 빨리 찾는 방법

Primary

```
alert_primary.log
```

Standby

```
alert_standby.log
```

대표 오류

```
ORA-16047
ORA-12514
ORA-16766
ORA-00313
```

Oracle Data Guard Broker

확인

```
dgmgrl
show configuration
```

또는

```
show database verbose standby;
```

# 🔟 Log transport mode 확인

Primary

```sql
SELECT dest_id, transmission_mode
FROM v$archive_dest;
```

모드

```
SYNC
ASYNC
```

SYNC인데 네트워크 문제 있으면 전송이 멈추는 경우 많습니다.

---

# 🚨 실무에서 가장 많이 걸리는 TOP 5

1️⃣ Standby redo log 없음

2️⃣ MRP 안 돌고 있음

3️⃣ archive gap 발생

4️⃣ TNS 설정 오류

5️⃣ DB_UNIQUE_NAME / LOG_ARCHIVE_CONFIG 설정 오류

---

# 🔎 DBA들이 바로 보는 **3개 뷰**

동기화 문제 생기면 이 3개부터 봅니다.

```sql
v$archive_dest_status
v$managed_standby
v$archive_gap
```

---

원하면 내가 **"Data Guard 동기화 안될 때 30초 진단 SQL 세트 (실무 DBA들이 바로 쓰는 것)"**도 정리해 줄게.

이거 하나면 **Primary / Standby 상태를 한 번에 판단**할 수 있습니다.
