# 데이터 가드 ORA-01152 해결방안

[](https://img1.daumcdn.net/thumb/C60x60/?fname=https://t1.daumcdn.net/cafe_image/img_profile/profile_angmond.png)

**게시글 본문내용**

[](https://t1.daumcdn.net/cafeattach/zchT/b00a6024112e80dbd5b9f1123abe9ce09d9deb5f)

ORA-01152: file 1 was not restored from a sufficiently old backup

원인 SCN 불일치

👉 컨트롤파일 / 데이터파일 / redo 시점 불일치

구체적으로:

- Standby controlfile을 새로 가져옴
- 하지만 standby datafile은 기존 상태 유지
- → SCN 불일치 발생
- → ORA-01152 발생

즉:

👉 “standby DB 시점이 깨진 상태”

- ---

일단 SBDB mount에서 MRP가 정상 작동하는지 확인

정상 작동이라면, PROD에서 REDO를 더 적용해서 SCN을 맞추면 됩니다.

alter system switch logfile;

alter system archive log current;

- --

SBDB에서 재개

alter database recover managed standby database disconnect from session;

- --

select sequence#, applied from v$archived_log;

여기서 No가 뜨면 좋은신호고 YES로 바뀌면 데이터가드가 정상적으로 연동했다는것을 확인할 수 있습니다.

THREAD#  SEQUENCE# APPLIED                     ARCHIVED  NAME

- --------- ---------- --------------------------- --------- ------------------------------------------------------------------------------------------

1         27 NO                          YES       /home/oracle/SBDB/arch/1_27_1229444164.dbf

1         26 NO                          YES       /home/oracle/SBDB/arch/1_26_1229444164.dbf

시간이 지난후

THREAD#  SEQUENCE# APPLIED    ARCHIVED  NAME

- --------- ---------- ---------- --------- ------------------------------------------------------------------------------

1         27 YES        YES       /home/oracle/SBDB/arch/1_27_1229444164.db

1         26 YES        YES       /home/oracle/SBDB/arch/1_26_1229444164.db

그 후에 PROD에서 emp update하고 SBDB에 적용이 되는지 확인

🎯 핵심 교훈

- ORA-01152 = 반드시 restore 해야 하는 건 아님
- v$archived_log.APPLIED 변화가 핵심 지표
- MRP0 WAIT_FOR_LOG 는 정상일 수 있음
- 실제 검증은
    
    데이터 반영 테스트가 가장 확실
