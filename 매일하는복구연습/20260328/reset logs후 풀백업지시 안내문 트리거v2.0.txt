V1.0의 아이디어는 결국 백업 유무의 판단의 모호함으로 인해 생각대로 동작하지 않았다. 그에 반해 resetlog이벤트 트리거는 잘 작동했기 때문에 트리거 발동시 테이블에 기록을 하고 백업유무 상태를 저장하여 관리자가 백업후 백업유무 상태컬럼을 변경하기 전까지 계속해서 sqlplus로그인 화면에 메시지를 출력하는 형식으로 변경하였다.

네, 완벽히 이해했습니다! 현재 `V$BACKUP_SET` 같은 동적 뷰를 직접 조회하는 방식은 **"Resetlogs 직후에 오라클이 자동으로 수행하는 컨트롤 파일 백업"**과 **"진짜 관리자가 수행한 데이터 풀 백업"**을 완벽히 구분하기 어려울 때가 있고, 시스템 상황에 따라 조회가 늦어질 수도 있죠.

사용자께서 제안하신 **"상태 저장용 테이블"**을 활용하는 방식이 훨씬 확실하고 관리하기 편합니다. 관리자가 "나 백업 다 했어!"라고 수동으로 업데이트하기 전까지는 계속 경고를 띄우는 **'체크리스트'** 방식을 구현해 보겠습니다.

### 🛠️ 구현 전략: 관리자 승인 기반 백업 확인 시스템

#### 1. 상태 저장용 테이블 생성 (관리자 계정)
먼저 백업 상태를 기록할 작은 테이블 하나를 만듭니다.
```sql
CREATE TABLE backup_check_status (
    db_name        VARCHAR2(30),
    last_resetlogs DATE,
    backup_status  VARCHAR2(10) DEFAULT 'REQUIRED', -- 'DONE' 또는 'REQUIRED'
    updated_at     DATE
);

-- 초기 데이터 삽입 (현재 DB 상태 반영)
INSERT INTO backup_check_status 
SELECT name, resetlogs_time, 'REQUIRED', SYSDATE FROM v$database;
COMMIT;
```

#### 2. Resetlogs 발생 시 상태를 'REQUIRED'로 변경하는 트리거
DB가 오픈될 때, 만약 `resetlogs_time`이 테이블에 기록된 시간과 다르다면(즉, 새로 Resetlogs가 발생했다면) 상태를 다시 'REQUIRED'로 바꿉니다.

```sql
CREATE OR REPLACE TRIGGER trg_resetlogs_update
AFTER STARTUP ON DATABASE
DECLARE
    -- 독립 트랜잭션으로 선언 (COMMIT 사용 가능해짐)
    PRAGMA AUTONOMOUS_TRANSACTION; 
    v_curr_reset DATE;
    v_last_reset DATE;
BEGIN
    -- 1. 현재 DB의 Resetlogs 시간 조회
    SELECT resetlogs_time INTO v_curr_reset FROM v$database;
    
    -- 2. 관리 테이블의 마지막 기록 조회
    SELECT last_resetlogs INTO v_last_reset FROM backup_check_status WHERE ROWNUM = 1;

    -- 3. 시간이 다르면 (새로운 인카네이션 발생 시) 업데이트
    IF v_curr_reset > v_last_reset THEN
        UPDATE backup_check_status
        SET last_resetlogs = v_curr_reset,
            backup_status = 'REQUIRED',
            updated_at = SYSDATE;
        
        COMMIT; -- 자율 트랜잭션 내에서는 커밋 가능
    END IF;

EXCEPTION 
    WHEN OTHERS THEN 
        NULL; 
END;
/
```

#### 3. 로그인할 때마다 메시지를 보여주는 프로시져 (AFTER LOGON)
이제 관리자(혹은 특정 사용자)가 로그인할 때마다 테이블을 조회해서 'REQUIRED' 상태면 경고를 띄웁니다.

```sql
CREATE OR REPLACE PROCEDURE check_backup_status AS
    v_status VARCHAR2(10);
    v_user   VARCHAR2(30);
BEGIN
    v_user := USER;

    -- 관리자 계정일 때만 체크 수행
    IF v_user IN ('SYS', 'SYSTEM') THEN
        BEGIN
            SELECT backup_status INTO v_status 
            FROM backup_check_status 
            WHERE ROWNUM = 1;

            IF v_status = 'REQUIRED' THEN
                DBMS_OUTPUT.PUT_LINE(' ');
                DBMS_OUTPUT.PUT_LINE('--------------------------------------------------');
                DBMS_OUTPUT.PUT_LINE('🚨 [ADMIN NOTICE] DATABASE WAS OPENED WITH RESETLOGS!');
                DBMS_OUTPUT.PUT_LINE('🚨 FULL BACKUP IS MANDATORY. PLEASE RUN RMAN BACKUP.');
                DBMS_OUTPUT.PUT_LINE('🚨 AFTER BACKUP, RUN: UPDATE backup_check_status SET backup_status = ''DONE'';');
                DBMS_OUTPUT.PUT_LINE('--------------------------------------------------');
                DBMS_OUTPUT.PUT_LINE(' ');
            END IF;
        EXCEPTION
            WHEN NO_DATA_FOUND THEN NULL;
            WHEN OTHERS THEN NULL;
        END;
    END IF;
END;
/
```
*(참고: `DBMS_OUTPUT` 결과를 보려면 클라이언트 도구에서 `SET SERVEROUTPUT ON` 설정이 되어 있어야 합니다.)*

#### 4. $ORACLE_HOME/sqlplus/admin/glogin.sql 설정
파일 맨 밑에 아래와 같이 순서대로 작성해 주세요.

SQL
-- 1. 메시지 출력을 잠시 활성화합니다.
SET SERVEROUTPUT ON SIZE UNLIMITED;

-- 2. 백업 체크 프로시저를 실행하여 경고문을 출력합니다.
EXEC check_backup_status;

-- 3. 출력이 끝났으므로 다시 메시지 기능을 끕니다.
SET SERVEROUTPUT OFF;

### 📝 관리자의 행동 강령 
이제 시스템은 수동 승인 방식으로 작동합니다.

1.  **장애 복구 완료:** `OPEN RESETLOGS`로 DB 오픈.
2.  **로그인 시 경고 발생:** 트리거가 자동으로 "백업하세요!" 메시지 출력.
3.  **실제 백업 수행:** RMAN 등을 이용하여 Full Backup 완료.
4.  **상태 업데이트 (승인):** 관리자가 직접 아래 명령어를 실행하여 경고를 끕니다.
    ```sql
    UPDATE backup_check_status SET backup_status = 'DONE', updated_at = SYSDATE;
    COMMIT;
    ```
