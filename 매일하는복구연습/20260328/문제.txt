실무와 시험에서 모두 중요하게 다루어지는 **RMAN을 이용한 불완전 복구(Incomplete Recovery)** 시나리오를 준비했습니다. 

이 시나리오는 데이터베이스의 물리적인 파손이 아니라, 사용자의 실수나 논리적 오류로 인해 특정 시점으로 되돌려야 하는 상황을 가정합니다.

---

### 🛠️ 오라클 복구 실습 시나리오: "과거로의 시간 여행"

**[상황 설정]**
중요한 결산 작업을 앞두고 한 운영자가 실수로 핵심 테이블을 삭제(Drop)하거나 데이터를 잘못 수정한 후 커밋(Commit)해 버렸습니다. Flashback 기술을 사용하기에는 보관 주기(Retention)가 지났거나 비활성화되어 있어, 반드시 **RMAN 백업본을 사용해 해당 사고 발생 직전 시점으로 전체 DB를 복구**해야 합니다.

**[고장 내기 (시나리오 실행)]**
1. 현재 시간을 확인합니다. (복구 목표 시점 확인용)
   ```sql
   SELECT TO_CHAR(SYSDATE, 'YYYY-MM-DD:HH24:MI:SS') FROM V$ACCESS;
   ```
2. 실수로 테이블을 삭제합니다.
   ```sql
   DROP TABLE HR.EMPLOYEES PURGE;
   ```
     제약조건 문제로 인해 아래 실행
     DROP TABLE HR.EMPLOYEES CASCADE CONSTRAINTS PURGE;
3. 현재 로그를 스위칭하여 사고 기록을 아카이브 로그에 저장합니다.
   ```sql
   ALTER SYSTEM SWITCH LOGFILE;
   ```

**[미션: 여러분의 해결 과제]**
현재 데이터베이스는 작동 중이지만, `HR.EMPLOYEES` 테이블은 사라진 상태입니다. 다음 단계에 따라 DB를 사고 직전 상태로 복구하세요.

1.  **DB 종료 및 마운트:** 데이터베이스를 정상 종료한 후 `MOUNT` 단계로 기동하세요.
2.  **시간 기반 복구 설정:** 사고 발생 전 시간을 지정하여 `SET UNTIL TIME` 명령을 작성하세요.
3.  **복구 실행:** RMAN에서 `RESTORE`와 `RECOVER`를 수행하세요.
4.  **DB 오픈:** 불완전 복구 이후에는 반드시 어떤 옵션으로 `OPEN` 해야 하는지 적용하여 DB를 활성화하세요.

**힌트:**
* `RUN { ... }` 블록을 사용하면 여러 명령어를 한 번에 처리하기 좋습니다.
* 복구 후에는 반드시 `ALTER DATABASE OPEN RESETLOGS;`가 필요합니다.
