유저 삭제(DROP USER), 테이블 드랍(DROP TABLE), 그리고 TRUNCATE와 같은 치명적인 작업은 데이터베이스의 뼈대를 흔드는 작업이라 반드시 기록을 남겨야 합니다.

오라클에서 이러한 행위를 추적하고 로그를 남기는 가장 확실한 방법 3가지를 정리해 드립니다.

1. 개념 설명
일반적인 DML(Insert, Update)과 달리, 구조를 바꾸는 **DDL(Data Definition Language)**이나 TRUNCATE는 기본적으로 리두 로그에 최소한의 정보만 남기기 때문에 나중에 "누가" 했는지 찾아내기가 어렵습니다. 이를 보완하기 위해 다음 기능들을 사용합니다.

Standard Auditing: 오라클의 전통적인 감사 기능으로, 특정 명령어 실행 시 기록을 남깁니다.

Unified Auditing (12c 이상 권장): 모든 감사 기록을 하나의 테이블에서 관리하며 성능이 더 좋습니다.

DDL Trigger: DDL이 발생할 때마다 커스텀 로그 테이블에 정보를 쌓는 방식입니다.

2. 문제 해설 (설정 방법)
A. Unified Auditing 사용 (가장 권장됨)
오라클 12c, 19c 환경이라면 이 방식을 사용하는 것이 가장 세련된 방법입니다. 

감사 정책 생성:

SQL
CREATE AUDIT POLICY critical_drop_actions
ACTIONS DROP USER, DROP TABLE, TRUNCATE TABLE, DROP TABLESPACE;
정책 활성화:

SQL
AUDIT POLICY critical_drop_actions;
로그 확인:

SQL
SELECT 
    TO_CHAR(event_timestamp, 'YYYY-MM-DD HH24:MI:SS') AS "시간",
    dbusername AS "DB유저",
    os_username AS "OS유저",
    userhost AS "호스트",
    action_name AS "작업",
    object_schema AS "대상스키마",
    object_name AS "대상객체"
FROM 
    unified_audit_trail
WHERE 
    action_name IN ('DROP USER', 'DROP TABLE', 'TRUNCATE TABLE', 'DROP TABLESPACE')
ORDER BY 
    event_timestamp DESC;

# 🕵️‍♂️ 실습 시나리오: 유저 삭제 사건 추적 및 로그 분석

[cite_start]이 시나리오는 누군가 `HR` 유저를 `DROP`했을 때, 당황하지 않고 **Audit Trail(감사 로그)**을 통해 범인의 정체와 정확한 범행 시각을 밝혀내는 과정을 다룹니다. [cite: 14]

---

## 1. 단계별 분석 절차

### **Step 1: 유저 부재 상황 인지**
[cite_start]애플리케이션 접속 에러나 관리 도구의 경고를 통해 `HR` 유저가 사라졌음을 확인합니다. [cite: 14]
* [cite_start]**상태 확인:** `SELECT username FROM dba_users WHERE username = 'HR';` 결과가 없음을 확인합니다. [cite: 14]

### **Step 2: 감사 정책(Audit Policy) 존재 여부 확인**
[cite_start]범인을 잡기 위해서는 사전에 감사 정책이 세워져 있어야 합니다. [cite: 12]
```sql
-- 현재 활성화된 감사 정책 확인
SELECT policy_name, enabled_opt 
FROM audit_unified_enabled_policies 
WHERE policy_name = 'CRITICAL_DROP_ACTIONS';
```

### **Step 3: 감사 로그(Audit Trail) 정밀 분석**
`Unified Audit Trail`은 DBA의 블랙박스와 같습니다. [cite_start]여기서 삭제 명령을 내린 유저와 터미널 정보를 추출합니다. [cite: 12]

```sql
-- DROP USER 행위의 '스모킹 건' 찾기
SELECT 
    TO_CHAR(event_timestamp, 'YYYY-MM-DD HH24:MI:SS') AS "범행시간",
    dbusername AS "실행계정",
    os_username AS "OS사용자",
    userhost AS "접속장비",
    terminal AS "터미널정보",
    return_code AS "성공여부"
FROM 
    unified_audit_trail
WHERE 
    action_name = 'DROP USER' 
    AND object_schema = 'HR'
ORDER BY 
    event_timestamp DESC;
```
* [cite_start]**결과 해석:** `return_code`가 **0**이면 삭제에 성공한 것이며, `dbusername`이 바로 범인의 계정입니다. [cite: 12, 14]

### **Step 4: 연쇄 피해 파악 (Alert Log 대조)**
[cite_start]유저가 삭제되면서 발생한 시스템 내부의 연쇄 반응을 `Alert Log`에서 확인합니다. [cite: 12]
* [cite_start]**확인 내용:** 테이블스페이스 내 세그먼트 삭제 기록이나 인덱스 언유저블(Unusable) 관련 메시지가 찍혔는지 대조합니다. [cite: 12]
