### 1단계: 원격 제약조건 정보를 로컬 임시 테이블로 복사

`LONG` 타입 컬럼(`SEARCH_CONDITION`)은 직접 복사가 안 되므로, 비교에 필요한 컬럼만 딱 골라서 가져옵니다.

SQL

```jsx
CREATE TABLE TEMP_REMOTE_CONS
TABLESPACE ts20000
AS
SELECT A.TABLE_NAME, B.COLUMN_NAME, A.CONSTRAINT_TYPE, B.POSITION 
FROM USER_CONSTRAINTS@SH_LINK A
JOIN USER_CONS_COLUMNS@SH_LINK B ON A.CONSTRAINT_NAME = B.CONSTRAINT_NAME;
AS
SELECT A.TABLE_NAME, B.COLUMN_NAME, A.CONSTRAINT_TYPE, B.POSITION 
FROM USER_CONSTRAINTS@HR_LINK A
JOIN USER_CONS_COLUMNS@HR_LINK B ON A.CONSTRAINT_NAME = B.CONSTRAINT_NAME;
```

### 2단계: 로컬 테이블끼리 `MINUS` 수행

이제 원격 데이터가 내 DB에 들어왔으므로, 컨텍스트 에러 없이 마음껏 비교할 수 있습니다.

SQL

```jsx
SELECT TABLE_NAME, COLUMN_NAME, CONSTRAINT_TYPE, POSITION
FROM TEMP_REMOTE_CONS
minus
SELECT TABLE_NAME, COLUMN_NAME, CONSTRAINT_TYPE, POSITION
FROM ( SELECT A.TABLE_NAME, B.COLUMN_NAME, A.CONSTRAINT_TYPE, B.POSITION
 FROM USER_CONSTRAINTS A JOIN USER_CONS_COLUMNS B ON A.CONSTRAINT_NAME = B.CONSTRAINT_NAME
);

SELECT TABLE_NAME, COLUMN_NAME, CONSTRAINT_TYPE, POSITION
FROM ( SELECT A.TABLE_NAME, B.COLUMN_NAME, A.CONSTRAINT_TYPE, B.POSITION
 FROM USER_CONSTRAINTS A JOIN USER_CONS_COLUMNS B ON A.CONSTRAINT_NAME = B.CONSTRAINT_NAME
)
MINUS
SELECT TABLE_NAME, COLUMN_NAME, CONSTRAINT_TYPE, POSITION
FROM TEMP_REMOTE_CONS;
```

3단계: 임시 테이블 삭제

## 👨‍🏫인덱스 차이 검증

**💡 더 정확한 검증을 위한 팁**
이관 전/후의 인덱스가 누락 없이 잘 넘어갔는지 확인하려면 `index_name`이 아닌, **테이블 이름과 인덱스가 걸린 컬럼**을 기준으로 비교하셔야 합니다. 아래와 같이 `user_ind_columns` 뷰를 활용해 보는 것을 권장해 드립니다.

```jsx
- 테이블명과 컬럼명을 기준으로 비교하는 예시
SELECT table_name, column_name FROM user_ind_columns
MINUS
SELECT table_name, column_name FROM user_ind_columns@sh_link;
```
