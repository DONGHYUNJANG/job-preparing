# 인덱스를 다른 테이블 스페이스로 옮기기

---

> 개념 설명
> 
- **성능 분산**: 데이터와 인덱스를 물리적으로 다른 디스크(테이블스페이스)에 배치하여 I/O 경합을 줄입니다.
- **관리 편의성**: 인덱스만 따로 관리하면 백업이나 테이블스페이스 유지보수가 용이해집니다.
- **Rebuild 효과**: 이동 과정에서 `REBUILD` 명령어를 사용하므로, 인덱스 트리의 밸런스가 잡히고 빈 공간이 정리됩니다.

> 주의사항
> 
- **잠금(Lock)**: 일반적인 `REBUILD`는 테이블에 독점 잠금을 걸어 DML을 차단합니다. 서비스 중이라면 `ONLINE` 옵션이 필수입니다.
- **리소스**: 인덱스 재생성 시 CPU와 Temp 테이블스페이스, Undo 공간을 많이 사용합니다.

> 인덱스 종류 별 이관/분리 권장 여부
> 

| **인덱스 종류** | **이관/분리 권장** | **성능(I/O) 관점의 배치** | **이유** |
| --- | --- | --- | --- |
| **일반 B-Tree** | **적극 권장** | 별도 디스크 분리 | 가장 확실한 I/O 분산 효과 |
| **비트맵(Bitmap)** | **권장** | 별도 디스크 분리 | 대용량 분석 쿼리 병렬 처리 유리 |
| **파티션 인덱스** | **선택 사항** | 테이블과 인접 배치 | 관리 편의성 vs I/O 분산 사이의 선택 |
| **LOB 인덱스** | **비권장** | LOB 데이터와 같은 곳 | 물리적 종속성이 강함 (MOVE LOB 필요) |
| **IOT** | **불가능** | **데이터와 합체** | **테이블 자체가 인덱스이므로 분할 불가** |
| **Domain Index** | **주의** | 애플리케이션 특성 따름 | 오라클 텍스트 등 외부 엔진 연동 가능성 |

## 🛠️ 스키마 전체 인덱스 합계 계산

"총 얼마나 이동해야 하는가?"를 알고 싶을 때 사용합니다.

```jsx
SELECT 
    OWNER,
    COUNT(*) AS INDEX_COUNT,
    -- MB 단위로 변경하고 소수점을 4자리까지 확인
    ROUND(SUM(BYTES) / 1024 / 1024, 4) AS TOTAL_MB,
    -- KB 단위도 같이 확인
    ROUND(SUM(BYTES) / 1024, 2) AS TOTAL_KB
FROM DBA_SEGMENTS
WHERE OWNER = 'SH'
  AND SEGMENT_TYPE LIKE '%INDEX%'
GROUP BY OWNER;

SELECT 
    SEGMENT_TYPE, 
    COUNT(*) AS CNT,
    ROUND(SUM(BYTES) / 1024 / 1024, 2) AS MB_SUM
FROM DBA_SEGMENTS
WHERE OWNER = 'SH'
  AND SEGMENT_TYPE LIKE '%INDEX%'
GROUP BY SEGMENT_TYPE;
```

## 📊 자원 산정 가이드 (Rule of Thumb)

### 리소스 계산 공식

| 리소스 | 권장 확보 용량 | 비고 |
| --- | --- | --- |
| Permanent (INDEX TS) | 인덱스 크기 × **2배** | 기존 인덱스와 새 인덱스가 잠시 공존 |
| Temp TS | 인덱스 크기 × **1.5배** | 정렬(Sort) 작업용 공간 |
| Undo TS | 인덱스 크기 × **10% ~ 20%** | `ONLINE` 옵션 시 트랜잭션 양에 따라 가변 |

### 🛠️ 실제 예시 (인덱스 크기 10GB)

- **테이블스페이스 여유**: 10GB 이상 (새 인덱스가 들어갈 자리)
- **Temp 공간**: 약 15GB 확보 권장
- **Undo 공간**: 평소보다 2~5GB 정도 더 여유 있게 확보 (작업 중 DML이 많다면 더 필요)

### 🔍 TEMP/UNDO 디폴트 확인 SQL

#### 1) 디폴트 TEMP 테이블스페이스 이름 확인

```sql
SELECT PROPERTY_VALUE AS DEFAULT_TEMP_TS
FROM DATABASE_PROPERTIES
WHERE PROPERTY_NAME = 'DEFAULT_TEMP_TABLESPACE';
```

#### 2) TEMP 테이블스페이스 용량/사용량 확인

```sql
-- TEMP 전체 할당/사용/여유 (현재 사용량 기준)
SELECT
  tf.tablespace_name,
  ROUND(SUM(tf.bytes)/1024/1024/1024, 2) AS total_gb,
  ROUND(SUM(NVL(th.bytes_used,0))/1024/1024/1024, 2) AS used_gb,
  ROUND((SUM(tf.bytes)-SUM(NVL(th.bytes_used,0)))/1024/1024/1024, 2) AS free_gb
FROM dba_temp_files tf
LEFT JOIN v$temp_space_header th
  ON th.tablespace_name = tf.tablespace_name
 AND th.file_id = tf.file_id
GROUP BY tf.tablespace_name
ORDER BY tf.tablespace_name;
```

#### 3) 디폴트 UNDO 테이블스페이스 이름 확인

```sql
SHOW PARAMETER undo_tablespace;
```

#### 4) UNDO 테이블스페이스 용량/사용량 확인

```sql
-- UNDO 전체 할당량(데이터파일 합)
SELECT
  tablespace_name,
  ROUND(SUM(bytes)/1024/1024/1024, 2) AS total_gb
FROM dba_data_files
WHERE tablespace_name = (SELECT value FROM v$parameter WHERE name = 'undo_tablespace')
GROUP BY tablespace_name;

-- UNDO 사용량(대략치: 데이터파일 - free)
SELECT
  df.tablespace_name,
  ROUND(SUM(df.bytes)/1024/1024/1024, 2) AS total_gb,
  ROUND((SUM(df.bytes)-SUM(fs.bytes))/1024/1024/1024, 2) AS used_gb,
  ROUND(SUM(fs.bytes)/1024/1024/1024, 2) AS free_gb
FROM dba_data_files df
JOIN (
  SELECT tablespace_name, SUM(bytes) AS bytes
  FROM dba_free_space
  GROUP BY tablespace_name
) fs
  ON fs.tablespace_name = df.tablespace_name
WHERE df.tablespace_name = (SELECT value FROM v$parameter WHERE name = 'undo_tablespace')
GROUP BY df.tablespace_name;
```

## 2. 인덱스 이동 스크립트

## 🛠️ PL/SQL로 자동 실행 (고급)

한 번에 자동으로 실행하고 싶다면 아래 블록을 활용하세요.

> 일반 인덱스
> 

```sql
BEGIN
  FOR idx IN (
    SELECT OWNER, INDEX_NAME
    FROM DBA_INDEXES
    WHERE OWNER = 'SCOTT'
      AND INDEX_TYPE = 'NORMAL'
  )
  LOOP
    EXECUTE IMMEDIATE 'ALTER INDEX ' || idx.OWNER || '.' || idx.INDEX_NAME ||
                      ' REBUILD TABLESPACE NEW_INDEX_TS ONLINE';
  END LOOP;
END;
/
```

> 파티션 인덱스 
주의!!! 파티션 인덱스도 이동할 것인지 확인을 받을것!!!!
> 

```jsx
BEGIN
  FOR idx IN (
    -- SH 스키마 중 아직 TS20000IDX로 옮겨지지 않은 '인덱스 파티션'들을 조회
    SELECT INDEX_OWNER, INDEX_NAME, PARTITION_NAME
    FROM DBA_IND_PARTITIONS
    WHERE INDEX_OWNER = 'SH'
      AND TABLESPACE_NAME != 'TS20000IDX'
  )
  LOOP
    -- 파티션 단위로 REBUILD 실행
    EXECUTE IMMEDIATE 'ALTER INDEX ' || idx.INDEX_OWNER || '.' || idx.INDEX_NAME || 
                      ' REBUILD PARTITION ' || idx.PARTITION_NAME || 
                      ' TABLESPACE TS20000IDX ONLINE';
  END LOOP;
END;
/
```

> !!! LOB 인덱스 이동은 테이블과 같이 관리하는 것이 정석이기 때문에 생략한다.
>

### 1) 목표 테이블스페이스로 변경됐는지(DBA_SEGMENTS)

```sql
SELECT
    TABLESPACE_NAME, 
    COUNT(*) AS INDEX_COUNT,
    ROUND(SUM(BYTES) / 1024 / 1024, 2) AS SIZE_MB
FROM DBA_SEGMENTS
WHERE OWNER = 'SH'
  AND SEGMENT_TYPE LIKE '%INDEX%'
GROUP BY TABLESPACE_NAME;
```
