## 1. 오라클의 비트맵 인덱스(Bitmap Index)란?

일반적인 B-Tree 인덱스는 테이블의 행(Row) 하나당 하나의 주소 값(ROWID)을 가집니다. 반면, **비트맵 인덱스는 데이터의 상태를 `0`과 `1`로 이루어진 지도(비트맵)로 만들어서 저장**합니다.

주로 **분포도가 낮은 컬럼**(값의 종류가 적은 컬럼, 예: 성별, 결혼 여부, 지역, 직급 등)에 생성할 때 엄청난 효율을 자랑합니다.

### 구조 예시 (성별 컬럼)

테이블에 5개의 행이 있고, 성별 컬럼이 있다고 가정해 보겠습니다. 오라클 내부에서는 이를 아래와 같이 비트(Bit) 배열로 변환하여 인덱스를 생성합니다.

| ROWID | 실제 데이터 (성별) | 비트맵: '남' | 비트맵: '여' |
| --- | --- | --- | --- |
| Row 1 | 남 | **1** | 0 |
| Row 2 | 여 | 0 | **1** |
| Row 3 | 남 | **1** | 0 |
| Row 4 | 남 | **1** | 0 |
| Row 5 | 여 | 0 | **1** |

## 2. 여기서 '비트와이즈(Bitwise)'는 어떻게 쓰이나요?

비트맵 인덱스의 진짜 강력함은 **여러 조건이 동시에 걸리는 복잡한 `WHERE` 절을 처리할 때** 나타납니다. 이때 오라클 옵티마이저가 내부적으로 **비트와이즈(AND, OR, NOT) 연산**을 수행합니다.

### 실전 예시: `WHERE 성별 = '남' AND 지역 = '서울'`

만약 성별 인덱스와 지역 인덱스가 각각 비트맵으로 존재한다면, 오라클은 디스크에서 무거운 데이터를 일일이 뒤지는 대신, 메모리 상에서 두 비트맵을 가져와 **비트와이즈 AND (`&`) 연산**을 해버립니다.

* **성별='남' 비트맵:** `1 0 1 1 0`
* **지역='서울' 비트맵:** `1 1 0 1 0`
* **비트와이즈 AND (`&`) 결과:** `1 0 0 1 0` (1번째, 4번째 행만 조건에 만족!)

> **💡 왜 빠를까?**
> 컴퓨터 CPU에게 `1 0 1 1 0`과 `1 1 0 1 0`을 AND 연산하라고 시키는 것은 수 나노초(ns)도 걸리지 않는 가장 가벼운 작업입니다. 수백만 건의 데이터도 비트 몇 개로 압축되어 순식간에 필터링되므로, 일반 인덱스보다 훨씬 빠른 속도로 결과를 찾아냅니다.

---

## 3. 비트맵 인덱스 + 비트와이즈의 장단점 요약

### 🎯 장점

* **다중 조건 검색에 탁월:** 여러 개의 비트맵 인덱스를 AND, OR로 조합하는 속도가 기가 막히게 빠릅니다.
* **저장 공간 절약:** 데이터가 `0`과 `1`로만 저장되고 내부적으로 압축도 되기 때문에 B-Tree 인덱스에 비해 용량을 아주 적게 차지합니다.

### ⚠️ 치명적인 단점 (국비 교육/시험 단골 주제)

* **DML(INSERT, UPDATE, DELETE)에 취약:** 비트맵 인덱스는 하나의 비트맵 블록에 수많은 행(Row)의 정보가 묶여 있습니다. 따라서 한 행만 수정하거나 추가해도 **해당 블록 전체에 락(Lock)이 걸립니다.** 다른 사용자가 다른 행을 수정하려고 해도 대기해야 하는 상황이 발생합니다.

> **📌 결론**
> 데이터가 빈번하게 수정되는 **OLTP(실시간 트랜잭션 중심) 시스템에서는 절대 쓰면 안 되며**, 데이터가 한 번 대량으로 입력된 후 조회 위주로 사용되는 **DW(데이터 웨어하우스)나 통계 시스템**에서 복잡한 조건을 빠르게 처리할 때 비트와이즈 연산과 함께 최고의 효율을 냅니다.
