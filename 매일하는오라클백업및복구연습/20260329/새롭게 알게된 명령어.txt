## 🛠️ Oracle RMAN 불완전 복구 핵심 명령어 가이드

### 1. `CATALOG START WITH` (물리 파일 강제 인식)
컨트롤 파일이 기억하지 못하는 아카이브 로그들을 장부에 등록하는 명령어입니다.

* **명령어 예시:**
    ```rman
    RMAN> CATALOG START WITH '/u01/app/oracle/fast_recovery_area/ORA19/archivelog/';
    ```
* **핵심 포인트:**
    * 지정한 경로의 **하위 폴더까지 자동으로 스캔**하여 유효한 로그를 찾습니다.
    * 컨트롤 파일을 백업본으로 복구했을 때, 그 이후에 생성된 로그들을 인식시키기 위한 **필수 단계**입니다.


---

### 2. `LIST ARCHIVELOG ALL` (장부 기록 확인)
현재 컨트롤 파일이 인식하고 있는 아카이브 로그 목록을 확인합니다.

* **명령어 예시:**
    ```rman
    RMAN> LIST ARCHIVELOG ALL;
    ```
* **핵심 포인트:**
    * `CATALOG` 명령 이후에 실행하여 파일 경로(`Name`)가 제대로 채워졌는지 확인하세요.
    * 여기서 번호(Sequence#)를 확인해야 `SET UNTIL`의 타겟을 정할 수 있습니다.

---

### 3. `SET UNTIL SEQUENCE` (복구 시점 지정)
데이터베이스를 특정 로그 시퀀스 번호 직전까지만 되돌리도록 설정합니다.

* **명령어 예시:**
    ```rman
    RUN {
      SET UNTIL SEQUENCE 5;  # 시퀀스 5번 '직전'까지 (즉, 4번까지만) 복구
      RESTORE DATABASE;
      RECOVER DATABASE;
      ALTER DATABASE OPEN RESETLOGS;
    }
    ```
* **핵심 포인트:**
    * 반드시 `RUN { ... }` 블록 내에서 다른 명령어들과 함께 사용해야 합니다.
    * 지정한 번호는 **포함되지 않는다**는 점을 꼭 기억하세요 (N-1까지 반영).


---

### 4. `V$ARCHIVED_LOG` (메타데이터 조회)
SQL*Plus에서 아카이브 로그의 등록 상태와 상세 정보를 조회합니다.

* **쿼리 예시:**
    ```sql
    SQL> SELECT THREAD#, SEQUENCE#, NAME, REGISTRAR 
         FROM V$ARCHIVED_LOG 
         ORDER BY SEQUENCE#;
    ```
* **핵심 포인트:**
    * `REGISTRAR` 컬럼을 통해 등록 주체를 확인합니다.
        * `ARCH`: 시스템이 자동 등록
        * `FGRD`: 사용자가 수동 등록 (오늘 실습의 핵심!)
        * `RMAN`: RMAN 작업 중 등록

---

### 💡 [실습 회고] 복구 프로세스 한눈에 보기 (Notion용)

1.  **STARTUP NOMOUNT**: DB 엔진만 가동.
2.  **RESTORE CONTROLFILE**: 과거의 장부(Control File) 복원.
3.  **ALTER DATABASE MOUNT**: 장부를 읽어 들임.
4.  **CATALOG START WITH**: 장부에 없는 실제 로그 파일들을 수동으로 기록.
5.  **RECOVER DATABASE**: 기록된 로그들을 이용해 데이터 파일에 변경 사항 반영.
6.  **OPEN RESETLOGS**: 시퀀스를 1번으로 초기화하며 복구 완료.
