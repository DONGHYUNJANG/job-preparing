
### 📊 실습 시나리오: 부서(Dept) - 사원(Emp) - 프로젝트(Proj)

* **상황:** 모든 부서는 출력되어야 하며, 부서에 속한 사원이 있다면 함께 보여줍니다. 그리고 사원이 참여 중인 프로젝트 정보도 보여주되, 사원이 없는 프로젝트 정보가 있다면 그것도 함께 보고 싶은 상황입니다.

#### **1. 스키마 및 데이터 세팅 (PostgreSQL)**

```sql
-- 1. 테이블 생성
CREATE TABLE dept (
    dept_id INT PRIMARY KEY,
    dept_name TEXT
);

CREATE TABLE emp (
    emp_id INT PRIMARY KEY,
    emp_name TEXT,
    dept_id INT
);

CREATE TABLE proj (
    proj_id INT PRIMARY KEY,
    emp_id INT,
    proj_name TEXT
);

-- 2. 데이터 삽입
INSERT INTO dept VALUES (10, 'Accounting'), (20, 'Research'), (30, 'Sales');
INSERT INTO emp VALUES (101, 'Alice', 10), (102, 'Bob', 10), (103, 'Charlie', 20);
-- 30번 Sales 부서는 사원이 없음
INSERT INTO proj VALUES (1, 101, 'Project-A'), (2, 999, 'Project-X'); 
-- Project-X는 현재 사원 명단에 없는 999번 사원이 담당 중 (Right Join 유도용)

-- 1. 부서 추가 (사원이 없는 부서, 프로젝트만 있는 부서 등)
INSERT INTO dept VALUES (40, 'Operation'), (50, 'Marketing');

-- 2. 사원 추가 
INSERT INTO emp VALUES 
(104, 'David', 20),   -- Research 부서 (사원 2명됨)
(105, 'Eve', NULL),   -- 부서가 없는 사원 (중요!)
(106, 'Frank', 40);   -- Operation 부서 사원

-- 3. 프로젝트 추가
INSERT INTO proj VALUES 
(3, 103, 'Project-B'), -- Charlie(20) 참여
(4, 105, 'Project-C'), -- 부서 없는 Eve(105) 참여
(5, NULL, 'Project-D'),-- 담당 사원이 아예 없는 프로젝트 (중요!)
(6, 101, 'Project-E'); -- Alice(10)가 두 번째로 참여하는 프로젝트 (데이터 뻥튀기 확인용)
```

### 📝 문제: "진짜 데이터 미로"

이제 데이터가 훨씬 복잡해졌습니다. 아래 요구사항을 반영한 **단 하나의 쿼리**를 짜보세요.

1.  **모든 부서명(`dept_name`)**이 일단 나와야 합니다.
2.  부서에 소속된 **사원명(`emp_name`)**을 연결합니다. (부서 없는 사원 `Eve`는 이 단계에서 어떻게 될까요?)
3.  여기에 **프로젝트명(`proj_name`)**을 연결합니다.
    * **조건 A:** 사원과 연결되지 않은 프로젝트(`Project-D`, `Project-X`)도 결과에 **무조건 포함**되어야 합니다.
    * **조건 B:** 반대로, 프로젝트에 참여하지 않은 사원(`Bob`, `Frank`)도 결과에 **무조건 포함**되어야 합니다.
4.  **필터링 조건 (가장 무서운 부분):** * 조인 결과에서 **부서명이 'Marketing'인 데이터는 아예 나오지 않게** 하세요.
    * 하지만 **부서명이 'Accounting'인 데이터는 '사원 이름이 Alice인 경우'에만** 조인되도록 하세요. (Alice가 아닌 Accounting 사원은 사원 정보가 NULL로 나와야 함)

#### **🎯 확인 포인트**
* `Left Join`과 `Right Join`을 섞었을 때, **부서 없는 사원(`Eve`)**이나 **사원 없는 프로젝트(`Project-D`)**가 최종 결과에서 살아남는지 확인하세요.
* `Full Outer Join`을 쓰지 않고 `Left/Right` 조합만으로 이 모든 유령 데이터를 살려낼 수 있는지 도전해 보세요.
