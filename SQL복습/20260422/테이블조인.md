9년 차 엔지니어의 그 '불안함'은 결국 **"어떤 데이터가 탈락(Drop)되거나, 원치 않게 복사(Fan-out)될까 봐"** 생기는 본능적인 감각입니다. 아주 좋은 신호예요.

이 불안함을 정면으로 돌파하기 위해, **Left와 Right가 뒤섞이고 조건의 위치가 결과에 결정적인 영향을 미치는** 실습 예제를 준비했습니다. 힌트 없이 드릴 테니, 결과가 어떻게 나올지 머릿속으로 먼저 그려보신 후 SQL을 작성해 보세요.

---

### 📊 실습 시나리오: 부서(Dept) - 사원(Emp) - 프로젝트(Proj)

* **상황:** 모든 부서는 출력되어야 하며, 부서에 속한 사원이 있다면 함께 보여줍니다. 그리고 사원이 참여 중인 프로젝트 정보도 보여주되, 사원이 없는 프로젝트 정보가 있다면 그것도 함께 보고 싶은 상황입니다.

#### **1. 스키마 및 데이터 세팅 (PostgreSQL)**

```sql
-- 1. 테이블 생성
CREATE TABLE dept (
    dept_id INT PRIMARY KEY,
    dept_name TEXT
);

CREATE TABLE emp (
    emp_id INT PRIMARY KEY,
    emp_name TEXT,
    dept_id INT
);

CREATE TABLE proj (
    proj_id INT PRIMARY KEY,
    emp_id INT,
    proj_name TEXT
);

-- 2. 데이터 삽입
INSERT INTO dept VALUES (10, 'Accounting'), (20, 'Research'), (30, 'Sales');
INSERT INTO emp VALUES (101, 'Alice', 10), (102, 'Bob', 10), (103, 'Charlie', 20);
-- 30번 Sales 부서는 사원이 없음
INSERT INTO proj VALUES (1, 101, 'Project-A'), (2, 999, 'Project-X'); 
-- Project-X는 현재 사원 명단에 없는 999번 사원이 담당 중 (Right Join 유도용)
```

### 📝 문제: 데이터의 미로 찾기

아래 요구사항을 **단 하나의 쿼리**로 작성해 보세요.

1.  **모든 부서명(`dept_name`)**이 일단 나와야 합니다. (사원이 없어도 출력)
2.  부서에 소속된 **사원명(`emp_name`)**을 연결합니다.
3.  여기에 **프로젝트명(`proj_name`)**을 연결하는데, **사원과 연결되지 않은 프로젝트(`Project-X`)도 결과에 포함**되어야 합니다.
4.  단, **부서명이 'Sales'인 경우의 데이터는 조인 과정에서 제외**되어야 합니다. (이 조건의 위치가 `ON`에 있느냐 `WHERE`에 있느냐에 따라 결과가 완전히 달라짐을 유의하세요.)

#### **🎯 미션**
* `Left Join`과 `Right Join`을 반드시 한 번씩 섞어서 사용해 보세요.
* 최종 결과 행(Row)이 몇 개가 나오는지, 그리고 `Project-X` 옆에 부서와 사원 정보가 어떻게 찍히는지 확인해 보세요.

### 📖 OCP/DB 실무 관전 포인트

* **개념 설명:** 3개 이상의 테이블을 조인할 때, `A Left Join B Right Join C` 순서라면 `(A Left Join B)`의 결과 집합이 하나의 테이블처럼 작동하여 `C`와 `Right Join`하게 됩니다.
* **문제 해설:** 999번 사원이 담당하는 `Project-X`는 `dept`나 `emp` 테이블과 조인될 때 공통 분모가 없습니다. 이 데이터가 최종 결과셋에서 어떤 'NULL' 값들을 달고 나오는지 분석하는 것이 이번 문제의 핵심입니다.
