동현 님의 요청에 맞춰 **복잡한 JOIN과 다중 테이블 처리**를 집중적으로 훈련할 수 있는 새로운 7일 계획을 짜보았습니다. 

단순히 문법을 익히는 게 아니라, 테이블 3~5개가 엮였을 때 **데이터가 어떻게 불어나고(Cross Join), 어떻게 사라지는지(Inner Join), 어떻게 보존되는지(Left Join)**를 몸소 느끼실 수 있도록 설계했습니다.

## 🏗️ 다중 테이블 JOIN 마스터링 7일 계획

### [1단계: 조인의 기초와 확장]
* **Day 1: Inner vs Left의 경계와 NULL 제어**
    * 3개 테이블(`주문-고객-배송`)을 조인하며, 고객 정보가 없거나 배송이 시작 안 된 데이터까지 포함해 리포트를 뽑는 법을 익힙니다.
* **Day 2: Self Join과 계층의 심화**
    * 지난 Recursive CTE의 연장선으로, 부서와 직원의 관계를 조인으로 풀고 상사와 직원을 한 행에 나열합니다.

### [2단계: 실전 비즈니스 데이터 모델링]
* **Day 3: 4개 테이블 연합 및 집계 (판매 분석)**
    * `상품-카테고리-주문-주문상세` 테이블을 조인하여 카테고리별 매출 비중을 계산합니다.
* **Day 4: Right Join과 Full Outer Join의 실무 사례**
    * 사실 거의 안 쓰지만, 특정 상황(누락된 마스터 데이터 찾기 등)에서 왜 필요한지 억지로 상황을 만들어 훈련합니다.

### [3단계: 복합 사고와 최적화]
* **Day 5: Cross Join을 활용한 데이터 증폭(Dummy Data)**
    * 날짜 테이블과 상품 테이블을 Cross Join하여 '판매가 없는 날'도 0으로 표시하는 실무 스킬을 배웁니다.
* **Day 6: 서브쿼리 vs 조인 (Inline View 활용)**
    * 5개 이상의 테이블이 얽힐 때 모든 걸 JOIN하지 않고, 서브쿼리로 먼저 데이터를 압축한 뒤 조인하는 전략을 배웁니다.
* **Day 7: 종합 응용 (재귀 + 다중 조인 + 윈도우 함수)**
    * 조직도(Recursive)와 매출(Join), 순위(Window)를 모두 섞은 최종 보스급 리포트를 작성합니다.

## 📅 Day 1: 3개 테이블 JOIN과 데이터 보존 (NULL 제어)

오늘 바로 시작해 볼까요? 

### 🗄️ 시나리오 및 테이블 스키마
쇼핑몰 데이터입니다. **모든 주문**을 조회하되, 고객 정보가 탈퇴했거나 배송 정보가 아직 생성되지 않은 경우도 누락 없이 보고 싶습니다.

#### 1. 테이블 생성 및 데이터
```sql
CREATE TABLE users (user_id INT PRIMARY KEY, user_name VARCHAR(50));
CREATE TABLE orders (order_id INT PRIMARY KEY, user_id INT, order_date DATE, amount NUMERIC);
CREATE TABLE shipping (ship_id INT PRIMARY KEY, order_id INT, status VARCHAR(20));

INSERT INTO users VALUES (1, '동현'), (2, '지현');
INSERT INTO orders VALUES (101, 1, '2026-04-20', 5000), (102, 3, '2026-04-21', 3000), (103, 1, '2026-04-21', 7000);
INSERT INTO shipping VALUES (501, 101, 'DELIVERED');
-- 102번 주문은 아직 배송 정보가 없고, 103번 주문은 배송 준비 중이라 테이블에 없음
```

### 📝 문제
1.  `orders` 테이블을 기준으로 `users`와 `shipping` 테이블을 결합하세요.
2.  **조건 1:** `user_id`가 3인 주문(탈퇴한 회원)의 경우 고객명을 'Unknown'으로 표시하세요.
3.  **조건 2:** 배송 정보가 없는 경우 상태를 'Preparing'으로 표시하세요.
4.  출력 컬럼: `order_id`, `user_name`, `amount`, `status`

---

### 🧠 DBA 실무 팁: 테이블이 늘어날 때의 사고방식
테이블이 5개, 10개로 늘어나면 머릿속으로 그림을 그리기 힘듭니다. 그때는 이 순서를 따르세요.

1.  **기준 테이블(Driving Table) 선정:** 가장 많은 정보를 담고 있거나, 내가 결과로 내고 싶은 핵심 행이 있는 테이블을 가장 왼쪽에 둡니다. (여기서는 `orders`)
2.  **한 놈씩 붙이기:** 처음부터 5개를 다 보지 말고, 1번+2번 조인 결과가 하나의 가상 테이블이라고 생각하고 거기에 3번을 붙이는 식으로 확장하세요.
3.  **Inner vs Left 결정:** "이 데이터를 붙일 때 왼쪽(기준) 데이터가 사라져도 되는가?"를 스스로에게 물으세요. 사라지면 안 되면 무조건 **LEFT JOIN**입니다.
