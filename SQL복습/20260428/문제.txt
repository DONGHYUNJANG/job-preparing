## **Day 6: 서브쿼리 vs 조인 (데이터 확장 버전)**

데이터 양이 적으면 쿼리 성능의 차이를 체감하기 어렵습니다. 이번에는 **사원 수와 프로젝트 할당 내역을 대폭 늘려**, 실제로 인라인 뷰를 통한 '데이터 압축'이 왜 필요한지 느낄 수 있도록 구성했습니다.

---

### **1. 확장된 데이터베이스 스키마 및 샘플 데이터**

아래 스크립트를 실행하여 기존 데이터를 삭제하고 더 풍성한 데이터를 삽입하세요. (PostgreSQL 전용 문법이 포함되어 있습니다.)

```sql
-- 기존 테이블 삭제 (초기화)
DROP TABLE IF EXISTS performance_reviews, project_assignments, projects, employees, departments;

-- 1. 부서 정보
CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(50)
);

-- 2. 사원 정보
CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    emp_name VARCHAR(50),
    dept_id INT REFERENCES departments(dept_id),
    hire_date DATE
);

-- 3. 프로젝트 정보
CREATE TABLE projects (
    proj_id INT PRIMARY KEY,
    proj_name VARCHAR(100),
    budget NUMERIC
);

-- 4. 프로젝트 할당 (데이터가 많이 쌓이는 트랜잭션 성격의 테이블)
CREATE TABLE project_assignments (
    assignment_id SERIAL PRIMARY KEY,
    emp_id INT REFERENCES employees(emp_id),
    proj_id INT REFERENCES projects(proj_id),
    hours_worked INT,
    work_date DATE
);

-- 5. 성과 지표 (KPI)
CREATE TABLE performance_reviews (
    review_id SERIAL PRIMARY KEY,
    emp_id INT REFERENCES employees(emp_id),
    review_year INT,
    rating INT CHECK (rating BETWEEN 1 AND 5)
);
```

// 1. 부서 정보
Table departments {
  dept_id int [pk]
  dept_name varchar
}

// 2. 사원 정보
Table employees {
  emp_id int [pk]
  emp_name varchar
  dept_id int [ref: > departments.dept_id]
  hire_date date
}

// 3. 프로젝트 정보
Table projects {
  proj_id int [pk]
  proj_name varchar
  budget numeric
}

// 4. 프로젝트 할당 (N:M 관계를 위한 중간 테이블)
Table project_assignments {
  assignment_id int [pk, increment]
  emp_id int [ref: > employees.emp_id]
  proj_id int [ref: > projects.proj_id]
  hours_worked int
  work_date date
}

// 5. 성과 지표
Table performance_reviews {
  review_id int [pk, increment]
  emp_id int [ref: > employees.emp_id]
  review_year int
  rating int
}

### **2. SQL 실습 문제 (심화)**

**[문제]**
2024년도 실적을 바탕으로 **'핵심 인재 리포트'**를 작성하려고 합니다. 다음 조건에 맞는 쿼리를 작성하세요.

1.  **필터링 조건:** * 2024년에 투입된 **총 근무 시간(`hours_worked`)의 합계가 80시간 이상**인 사원만 추출하세요.
2.  **인라인 뷰 활용 전략:** * `project_assignments` 테이블에서 사원별 `total_hours`를 먼저 집계하고 80시간 이상인 사원 ID만 걸러내는 **서브쿼리(Inline View)**를 작성하세요.
    * 해당 서브쿼리의 결과를 `employees`, `departments`, `performance_reviews`, `projects` 등과 조인하세요.
3.  **출력 컬럼:**
    * `emp_name` (사원명)
    * `dept_name` (부서명)
    * `total_hours_2024` (2024년 총 근무 시간 합계)
    * `current_rating` (2024년 성과 등급)
    * `assigned_projects` (참여한 프로젝트들의 이름을 쉼표로 구분하여 출력)
4.  **정렬:**
    * `total_hours_2024`를 기준으로 내림차순 정렬하세요.
