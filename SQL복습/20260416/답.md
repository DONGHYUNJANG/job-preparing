### 나의 답:
```sql
select a.*
, COALESCE(
round(
NULLIF((a.amount - a.prev_year), 0)
/ NULLIF(a.prev_year, 0) * 100.0
, 2)
, 0) as yoy
from
(select sale_date
, amount
, COALESCE(lag(amount, 1) over (order by sale_date) , 0) as prev_day
, COALESCE(lag(amount, 1) over (partition by to_char(sale_date, 'MM-DD') order by sale_date), 0) as prev_year
from daily_sales
where category = 'Electronics') a;
```sql

### 🔍 오타 및 교정 (Typos & Correction)

* **오타 체크**: `NULLIF((a.amount - a.prev_year), 0)` 부분에서 분자를 `NULLIF`로 감싸셨는데, 분자가 0인 것은 수학적으로 에러가 아닙니다 ($0 / 100 = 0$). 에러는 오직 **분모가 0일 때**만 발생하므로 분자에는 `NULLIF`를 쓸 필요가 없습니다.
* **타입 변환**: PostgreSQL에서는 정수형끼리 계산하면 결과도 정수가 되어 소수점이 잘릴 수 있습니다. `100.0`을 곱해줌으로써 암시적 형변환을 유도하신 점은 아주 훌륭한 센스입니다!

### 📖 개념 설명: 시차 분석과 데이터 무결성

OCP 시험이나 고급 SQL 설계에서 가장 중요한 것은 **'데이터가 비어있을 때(Gap)'**의 처리입니다.

1.  **PARTITION BY to_char(...)**: 날짜를 'MM-DD'로 추출해 파티션을 나누는 방식은 기발합니다. 하지만 특정 연도의 해당 날짜 데이터가 아예 누락(Missing Row)되어 있다면, `LAG(..., 1)`은 그 이전 연도가 아닌 **그보다 더 과거의 동일 날짜**를 가져올 위험이 있습니다.
-> ORDER BY EXTRACT(YEAR FROM sale_date) 부분을 이야기 하는것이다. 
2.  **COALESCE의 위치**: 윈도우 함수 결과에 바로 `COALESCE`를 쓰면, "데이터는 존재하지만 값이 NULL인 경우"와 "데이터 자체가 존재하지 않는 경우"를 모두 0으로 처리하게 됩니다.

### 📝 문제 해설 및 최적화 쿼리

제시하신 쿼리를 바탕으로, 더 안전하고 정확한 형태의 정답 코드를 제안해 드립니다.

```sql
SELECT 
    a.*,
    -- 분모에만 NULLIF를 사용하여 Zero Divide 방지
    -- 계산 전체를 COALESCE로 감싸 결과가 NULL일 때 0으로 표시
    COALESCE(
        ROUND(
            (a.amount - a.prev_year) / NULLIF(a.prev_year, 0) * 100.0, 
            2
        ), 
        0
    ) AS yoy
FROM (
    SELECT 
        sale_date,
        amount,
        -- 전일 매출: 날짜 순서대로 바로 위 행
        COALESCE(LAG(amount, 1) OVER (ORDER BY sale_date), 0) AS prev_day,
        -- 전년 매출: '월-일'이 같은 데이터끼리 모아서 연도순 정렬 후 이전 행
        COALESCE(
            LAG(amount, 1) OVER (
                PARTITION BY TO_CHAR(sale_date, 'MM-DD') 
                ORDER BY EXTRACT(YEAR FROM sale_date)
            ), 
            0
        ) AS prev_year
    FROM daily_sales
    WHERE category = 'Electronics'
) a;
```

**[해설]**
1.  **Inner Query (Subquery a)**: 
    * `prev_year` 계산 시 `ORDER BY`에 `EXTRACT(YEAR FROM sale_date)`를 명시하여 연도 순서대로 정확히 이전 값을 가져오도록 보강했습니다.
2.  **Outer Query**:
    * `yoy` 계산 시 분자의 `NULLIF`를 제거하여 로직을 단순화했습니다.
    * 분모가 0이 되어 `NULL`이 반환될 경우, 가장 바깥의 `COALESCE`가 이를 0으로 깔끔하게 치환합니다.
