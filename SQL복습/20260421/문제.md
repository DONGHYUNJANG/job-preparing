## 📅 Day 6: 재귀적 사고와 윈도우의 결합 (Advanced)

오늘의 훈련은 **Recursive CTE**를 사용하여 데이터의 계층 구조(Hierarchy)를 평면화하고, 그 위에서 **Window Function**을 활용해 부모 노드와의 통계적 관계를 분석하는 복합적인 SQL 작성 능력을 기르는 것입니다.

---

### 🗄️ 시나리오 및 테이블 스키마

어느 글로벌 유통 기업의 조직도와 각 부서별 당월 매출 데이터가 있습니다. 부서는 트리 구조로 연결되어 있으며, 최상위 부서(본부)부터 최하위 팀까지 구성되어 있습니다.

#### 1. 테이블 생성 (Schema)

```sql
CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_name VARCHAR(100),
    parent_id INT, -- 상위 부서 ID
    revenue NUMERIC(15, 2), -- 해당 부서 자체의 매출
    CONSTRAINT fk_parent FOREIGN KEY (parent_id) REFERENCES departments(dept_id)
);
```

#### 2. 테스트 데이터 (Insert Data)

```sql
INSERT INTO departments (dept_id, dept_name, parent_id, revenue) VALUES
(1, 'Global HQ', NULL, 500000),
(2, 'Asia Division', 1, 300000),
```

### 📝 문제

`departments` 테이블을 사용하여 다음 조건에 맞는 결과셋을 출력하는 SQL을 작성하세요.

1.  **Recursive CTE**를 사용하여 최상위 부서(`Global HQ`)부터 각 부서의 계층 구조를 추적하세요.
    * `depth`: 최상위 부서를 1로 시작하여 하위로 갈수록 1씩 증가합니다.
    * `path`: 부서 이름을 `>` 구분자로 연결하여 전체 경로를 표시하세요. (예: `Global HQ > Asia Division > Korea Branch`)
2.  각 행에는 다음의 컬럼이 포함되어야 합니다.
    * `dept_id`, `dept_name`, `depth`, `path`, `revenue`
3.  **윈도우 함수**를 사용하여 다음 분석 지표를 추가하세요.
    * `avg_revenue_at_depth`: 동일한 레벨(depth)에 있는 부서들의 평균 매출
    * `parent_revenue`: 해당 부서의 **직속 상위 부서**의 매출 (최상위 부서의 경우 0 또는 NULL)
    * `pct_of_parent`: 상위 부서 매출 대비 현재 부서 매출의 비중 (%)
4.  정렬 순서는 `path`를 기준으로 하세요.
