1. Hash Right Join의 의미
우변(Right) 테이블이 빌드(Build) 대상: A Right Join B라면, 오른쪽에 있는 B 테이블을 먼저 읽어서 메모리에 해시 구조로 저장합니다.

보통 옵티마이저는 크기가 더 작은 테이블을 메모리(Build Input)에 올리는 것이 유리하다고 판단할 때 방향을 결정합니다.
2. 왜 내 쿼리에서는 Right Join이 나왔을까?
작성하신 쿼리 플랜의 흐름을 보면:
products (pr) 테이블을 먼저 해시로 만듭니다. (Hash 단계)
그 뒤에 들어오는 order_items (ori)를 프로브(Probe)로 써서 연결합니다.
이 과정에서 order_items가 중심이 되어 products를 붙이는 형태가 되었기 때문에 Right Join 형태의 계획이 수립된 것입니다.
3. 드라이빙 테이블 관점
엄밀히 말하면 Hash Join에서는 '드라이빙'이라는 용어 대신 Build(해시 생성)와 Probe(검색)라는 용어를 씁니다.
Build Input: 메모리에 먼저 올라가는 테이블 (보통 더 작은 테이블)

hash는 hash테이블로 만든다는 말이고?
네, 정확합니다. Hash Join에서 'Hash'는 조인할 테이블 중 하나를 골라 메모리에 해시 테이블(Hash Table)이라는 자료구조로 만든다는 뜻입니다.
쉽게 비유하자면 이런 과정입니다.
1. 해시 테이블 만들기 (Build 단계)
행동: 한쪽 테이블(보통 더 작은 쪽)을 읽어서 조인 키(ID)를 해시 함수에 통과시킵니다.
결과: 메모리상의 특정 '바구니(Bucket)'에 데이터를 담아둡니다. (예: 101번 상품은 1번 바구니, 102번은 5번 바구니...)
장점: 이제 특정 ID를 찾을 때 처음부터 끝까지 뒤질 필요 없이, 해시 함수만 돌리면 어느 바구니에 있는지 즉시(O(1)) 알 수 있습니다.
2. 해시 테이블 뒤지기 (Probe 단계)
행동: 다른 쪽 테이블을 한 줄씩 읽으면서, 그 줄의 조인 키를 똑같이 해시 함수에 넣습니다.
결과: "어? 5번 바구니에 데이터가 있네!" 하고 즉시 연결합니다.
정리하자면
Hash Join: 한쪽을 메모리에 사전(Dictionary)처럼 만들어두고, 다른 쪽을 읽으면서 사전에서 단어를 찾듯 매칭하는 방식입니다.
Merge Join (아까 소트했던 거): 양쪽을 가나다순으로 정렬한 뒤, 위에서부터 아래로 동시에 내려오며 맞추는 방식입니다.
왜 이번엔 해시를 썼을까?
PostgreSQL이 보기에 order_items나 products는 데이터가 적어서 메모리에 사전(해시 테이블)을 통째로 만들어도 부담이 없다고 판단했기 때문입니다. 정렬(Sort)하는 것보다 해시를 만드는 게 더 빠를 것 같을 때 주로 이 방식을 선택합니다.
